# Лабораторная работа №4: Межпроцессное взаимодействие и синхронизация (WinAPI)

## Обзор проекта
Проект реализует систему передачи сообщений между независимыми процессами через общий бинарный файл. Система построена по модели «Многие ко многим»: один процесс **Receiver** (Приемник) координирует работу нескольких процессов **Sender** (Отправитель).

**Основная цель:** изучение механизмов межпроцессного взаимодействия (IPC) и синхронизации доступа к разделяемому ресурсу с использованием мьютексов и семафоров.

---

## Архитектура системы

### Общий ресурс: Кольцевая очередь (FIFO)
Передача сообщений организована через бинарный файл как **циклическая очередь**. Это гарантирует:
*   Соблюдение порядка сообщений (первым пришел — первым ушел).
*   Эффективное использование выделенного пространства в файле.

### 1. Процесс Receiver (Потребитель)
*   Создает бинарный файл и задает его емкость.
*   Запускает процессы `Sender` и дожидается их готовности.
*   В цикле считывает сообщения из файла. 
*   **Логика ожидания:** если очередь пуста, процесс переходит в состояние ожидания (блокируется), пока не появится новое сообщение.

### 2. Процесс Sender (Производитель)
*   Подключается к существующему файлу.
*   Сигнализирует о своей готовности к работе.
*   В цикле отправляет текстовые сообщения (до 20 символов).
*   **Логика ожидания:** если очередь заполнена, процесс блокируется до тех пор, пока `Receiver` не прочитает хотя бы одно сообщение и не освободит место.

---

## Механизмы синхронизации

Для корректной работы системы использованы следующие объекты WinAPI:
*   **Мьютекс (`Mutex`):** обеспечивает эксклюзивный доступ к файлу. Только один процесс (либо `Receiver`, либо один из `Sender`) может выполнять запись или чтение в конкретный момент времени.
*   **Семафоры (`Semaphores`):**
    *   `Empty Sem`: отслеживает количество свободных ячеек в очереди.
    *   `Full Sem`: отслеживает количество готовых сообщений для чтения.
*   **События (`Events`):** используются для подтверждения готовности всех процессов `Sender` перед началом обмена данными.

## Структура сообщения
Максимальная длина сообщения — **20 символов**. Каждое сообщение записывается в бинарный файл как фиксированный блок данных для упрощения навигации по кольцевой очереди.

## Инструкция по запуску
1. Скомпилируйте исходные коды `Receiver.cpp` и `Sender.cpp`.
2. Убедитесь, что оба `.exe` файла находятся в одной директории.
3. Запустите `Receiver.exe`.
4. Введите параметры файла и количество отправителей.
5. Используйте консоли отправителей для ввода текста и консоль приемника для чтения.
