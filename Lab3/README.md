# Лабораторная работа №3: Синхронизация потоков (Критические секции и События)

## Обзор проекта
Проект представляет собой многопоточное приложение, моделирующее конкуренцию потоков за общие ресурсы. Основной поток (`main`) управляет группой рабочих потоков (`marker`), которые пытаются «пометить» как можно больше элементов в общем массиве.

**Основная цель:** практическое применение механизмов синхронизации WinAPI (**Critical Sections** для защиты данных и **Events** для передачи сигналов) и решение проблем взаимной блокировки потоков.

---

## Логика работы системы

### 1. Поток main (Управляющий)
*   **Инициализация:** выделяет память под массив и запускает заданное количество потоков `marker`.
*   **Управление циклом:** 
    *   Подает сигнал к началу работы.
    *   Ожидает, пока все активные потоки не «зайдут в тупик» (не смогут найти свободную ячейку).
    *   Отображает текущее состояние массива.
    *   Принимает решение о завершении одного из потоков по выбору пользователя.
*   **Завершение:** освобождает ресурсы и координирует корректный выход оставшихся потоков.

### 2. Потоки marker (Рабочие)
*   **Маркировка:** генерируют случайный индекс и, если ячейка свободна (`0`), записывают туда свой номер.
*   **Синхронизация:** перед каждой записью поток «засыпает», имитируя выполнение работы.
*   **Режим ожидания:** если поток натыкается на занятую ячейку, он сообщает об этом главному потоку и приостанавливается до получения дальнейших инструкций.
*   **Очистка данных:** перед завершением работы поток обязан стереть все свои метки из массива, освобождая место для других.

---

## Технические особенности реализации

*   **Критические секции (`CRITICAL_SECTION`):** использованы для предотвращения состояния гонки (**Race Condition**) при проверке и записи в общий массив. Это гарантирует, что два маркера не пометят одну и ту же ячейку одновременно.
*   **События (`Events` / `CreateEvent`):** 
    *   Используются массивы событий для двусторонней связи между `main` и каждым потоком `marker`.
    *   Реализована логика «старт», «стоп» и «невозможность продолжения».
*   **Работа с динамической памятью:** корректное выделение и очистка массива целых чисел в зависимости от ввода пользователя.

## Инструкция по запуску
1. Скомпилируйте проект в среде Visual Studio.
2. При запуске укажите размерность массива (например, `20`) и количество потоков (например, `5`).
3. Следите за выводом: когда все потоки остановятся, выберите номер потока для удаления.
4. Наблюдайте, как освобождаются ячейки массива и оставшиеся потоки продолжают борьбу за ресурсы.
