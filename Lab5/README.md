# Лабораторная работа №5: Обмен данными по именованным каналам (WinAPI)

## Обзор проекта
Проект реализует клиент-серверное приложение для управления доступом к базе данных сотрудников через **именованные каналы (Named Pipes)**. Сервер координирует одновременную работу нескольких клиентов, обеспечивая целостность данных при параллельном чтении и модификации записей.

**Основная цель:** изучение механизмов межпроцессного взаимодействия (IPC) через каналы и реализация сложной логики синхронизации доступа к ресурсам.

---

## Архитектура системы

### Процесс-Сервер
Центральный узел системы, который:
*   Создает и инициализирует бинарную базу данных сотрудников.
*   Создает именованные каналы для связи с клиентами.
*   **Управляет блокировками:**
    *   **Режим чтения:** разрешает одновременный доступ нескольким читателям к одной записи.
    *   **Режим модификации:** блокирует запись для всех остальных клиентов (и читателей, и писателей) до завершения правки.
*   Синхронизирует транзакции и выводит финальное состояние файла после завершения всех сессий.

### Процесс-Клиент
Интерактивная утилита для удаленной работы с данными:
*   Подключается к серверу по ключу (ID сотрудника).
*   **Операции:**
    *   `Чтение`: получение данных записи без блокировки других читателей.
    *   `Модификация`: захват записи, изменение полей и отправка обновленной версии обратно на сервер.

---

## Технические особенности реализации

*   **Named Pipes:** использование `CreateNamedPipe` и `ConnectNamedPipe` для организации дуплексной связи между процессами.
*   **Протокол синхронизации:** реализация логики блокировок на стороне сервера. Использование мьютексов или событий для управления очередью запросов к конкретным ID.
*   **Транзакционность:** клиент «удерживает» доступ к записи во время редактирования, что предотвращает проблему «потерянного обновления» (Lost Update).
